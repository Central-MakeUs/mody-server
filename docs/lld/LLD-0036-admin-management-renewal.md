# LLD-0036: 관리자 관리 화면 리뉴얼 및 인증·챌린지 현황

| 항목 | 값 |

## 1. 목적 / 배경

기존 관리 화면을 인증 피드의 노란색·보라색 브랜드, 사이드 메뉴, 계정·환경 표시와 통일한다.
인증 피드의 `24건`은 처음 불러온 페이지 크기였으며 기간 전체 수가 아니었다.
기간 변경은 조회 버튼을 누를 때만 반영되어 숫자가 바뀌지 않는 것으로 보였다.
또한 기존 그룹별 주간 챌린지 조회는 전역 연결분을 제외하므로 실제 챌린지가 있어도 빈 목록을 반환했다.
기존 API 계약을 바꾸지 않고 관리 화면용 통합 조회와 전체 집계를 추가한다.

## 2. 범위

- `/admin`: 날짜 자동 적용, 오늘·7일·30일, 필터별 전체 인증 집계와 현재 표시 수 구분.
- `/admin/challenges`: 주간 챌린지와 그룹 관리 메뉴 분리, 공통 디자인 및 모바일 대응.
- 그룹 검색, 구성원과 초대 코드 조회, 그룹명 수정, 활동 기록 기간·종류·검색·페이지 처리.
- 전역·그룹 개별 챌린지 조회, 등록·수정·삭제, 전역 그룹 동기화와 인증 피드 연결.
- 기존 Google 세션·역할·CSRF 검사 유지. 공유 기록·전역 변경의 영향 범위와 삭제 전 확인 제공.
- 신규 인증 저장, 회원 제재, 관리자 초대 화면, 이미지 변환 서비스, 운영 배포는 포함하지 않는다.

## 3. 인터페이스 / API

### 인증 목록 및 집계

`GET /api/v1/admin/feed/summary`

- 목록과 동일한 `from`, `to`, `type`, `memberId`, `groupId`, `groupChallengeId`,
  `globalWeeklyChallengeId`, `keyword` 필터를 받는다. `cursor`, `size`와 무관하다.
- 한국시간 기준 양끝 날짜를 포함하며 최대 366일이다. 기본 최근 7일이다.
- 응답: `totalCount`, `mealCount`, `exerciseCount`, `challengeCount`, `from`, `to`, `timezone`.
- 목록에도 `globalWeeklyChallengeId`를 추가한다. `ACTIVITY`는 식사·운동만 조회하는 필터이며
  실제 응답 종류와 커서 종류는 기존 `MEAL`, `EXERCISE`, `CHALLENGE`를 유지한다.
- 공유 활동 기록은 `EXISTS` 조건을 사용해 한 기록당 한 번만 집계한다.
- 목록의 `groupRecordEditable`은 요청한 그룹의 활성 공유 매핑이 있는지 표시한다.
  매핑이 없는 이전 기록은 조회를 유지하되 그룹 관리에서 수정·삭제 버튼을 제공하지 않는다.
  이 플래그는 권한을 부여하지 않는다. 변경 API의 기존 서버 검사는 그대로 유지한다.

### 주간 챌린지 현황

`GET /api/v1/admin/challenge-overview`

- `from`, `to`: 챌린지 기간과 겹치는 항목. 기본 최근 90일~향후 30일, 최대 366일.
- `groupId`: 미지정 시 전역 원본과 그룹 개별 챌린지를 보여주고 전역 복제본의 중복 표시는 제외한다.
  지정 시 해당 그룹의 개별 챌린지와 전역 연결분을 모두 보여준다. 없는 활성 그룹은 404.
- `phase`: `ALL`, `ACTIVE`, `UPCOMING`, `ENDED`. 한국시간 오늘과 기간 양끝을 비교한다.
- `keyword`: 제목·안내 검색. `%`, `_`는 문자로 검색하며 최대 100자.
- `size`: 기본 24, 최대 100. `cursor`: 시작일·종류·ID 내림차순 키셋 커서.
- 응답: `items`, `totalCount`, `summary`, `hasMore`, `nextCursor`, `from`, `to`, `timezone`.
  `totalCount`는 상태 필터까지 적용한 전체 수이고, `summary`는 기간·그룹·검색어에 대한
  전체/진행 중/예정/종료 수로 상태 탭 전환 전후 동일한 기준이다.
- 항목: 문자열 `id`, `kind`(GLOBAL/GROUP), 제목·안내·시작·종료일,
  전역 ID·그룹 ID·그룹명, `phase`, 활성 연결 그룹 수, 인증 수, 참여 회원 수, 인증 참여 그룹 수.
- 인증 통계는 선택 조회 기간이 아니라 **각 챌린지의 전체 인증 기간** 내 유효 인증 기준이다.
  종료일 다음 날 0시 미만까지 포함하고 삭제된 인증·챌린지·그룹은 제외한다.
  참여 회원은 그룹을 가로질러 중복 제거한다. 활성 연결 그룹과 실제 인증 참여 그룹을 구분한다.
- 기존 `/weekly-challenges`, `/groups/{id}/weekly-challenges`, 기록·그룹 변경 API는 유지한다.

## 4. 데이터 모델

기존 활동 기록·공유 매핑·챌린지 인증·전역/그룹 챌린지 테이블을 조회한다.
새 테이블, 컬럼 또는 데이터 보정은 필요하지 않다.

## 5. 처리 흐름 / 사용성

- 인증 집계와 목록은 같은 필터 생성 함수를 사용한다. 집계는 페이지 제한 없이 종류별 COUNT한다.
  목록은 기존 소스별 제한과 키셋 페이지 처리를 유지한다.
- 주간 조회는 전체·상태 집계 1회, 페이지 조회 1회, 페이지 ID들의 통계 일괄 조회 1회이다.
  그룹 지정 시 활성 그룹 존재 확인 1회를 추가한다. 항목별 통계 쿼리를 실행하지 않는다.
- 전체 건수와 현재 표시 수를 구분한다. 집계 실패 시 숫자를 추정하거나 표시 수로 대체하지 않는다.
- 날짜·종류·그룹 변경은 자동 적용한다. 텍스트 검색은 조회 버튼/Enter로 적용하며 미적용 안내를 표시한다.
- 이전 요청은 취소하고 세대 번호를 확인하여 늦게 도착한 응답이 새 필터 결과를 덮지 않게 한다.
- 그룹 활동 기록은 최근 30일·24건으로 시작하고 더 보기를 제공한다. 이미지 원본은 지연 로딩한다.
  실제 썸네일 파일 생성·대역폭 최적화는 이번 변경에 포함하지 않는다.
- 전역 연결분은 그룹에서 임의 수정하지 않고 원본 관리로 연결한다.
- 전역 등록·수정·삭제는 모든 연결 그룹에 대한 영향을 표시한다.
  활동 기록 수정·삭제는 공유된 다른 그룹의 원본·댓글에도 영향을 준다는 것을 표시한다.
- 변경 요청 중 중복 제출을 막고 전역 신규 등록에는 재시도용 Idempotency-Key를 유지한다.
  변경 대상 ID는 제출/확인 시 캡처하여 그룹 선택 변경과 섞이지 않도록 한다.
- VIEWER는 동적으로 생성된 버튼을 포함해 변경 버튼이 비활성화되고 조회 전용 안내가 표시된다.
  서버의 역할·CSRF 검사가 최종 권한 판단이며 관리자 API 키를 브라우저에 전달하지 않는다.

## 6. 예외 / 에러 처리

잘못된 필터·기간·커서는 400, 비활성/없는 그룹은 404다. 인증·권한 오류는 기존 공통 정책을 따른다.
화면은 로딩·빈 목록·실패·읽기 전용을 구분하고 변경 실패 시 입력 대화상자를 유지한다.
로그인이 만료되거나 조회 권한이 회수되면 관리 화면을 감추고 로그인으로 안내한다.

## 7. 인수조건

- [x] 24건보다 많은 인증도 기간 전체 수가 정확하고 기간 변경 시 자동 갱신된다.
- [x] 그룹별 목록에 전역 연결분이 나타나고 전역 원본 관리 경로가 구분된다.
- [x] 연결 그룹·인증·중복 제거 참여자 수를 일괄 조회한다.
- [x] 그룹·구성원·활동 기록 관리와 기존 권한/CSRF 검사를 유지한다.
- [x] 집계 실패 후 더 보기를 해도 전체 집계 실패 상태가 유지된다.
- [x] H2·MySQL에서 조회/집계, 세션 통합 및 브라우저 동작·모바일 화면을 확인한다.

## 8. 영향 범위 / 배포

정적 관리 화면과 관리자 조회 API 변경이다. 앱의 일반 사용자 API 및 배포 구성은 변경하지 않는다.
DB 마이그레이션과 새 환경변수는 없다. 사용자가 직접 배포할 수 있도록 PR만 생성하고 자동 머지하지 않는다.
디자인 검토용 미리보기에는 샘플 데이터만 사용하며 실서비스 로그인 우회는 만들지 않는다.
